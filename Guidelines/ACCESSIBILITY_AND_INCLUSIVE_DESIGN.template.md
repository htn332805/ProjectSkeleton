## 2) Principles

- Perceivable: information must be presented in ways users can perceive.
- Operable: users can interact with all controls.
- Understandable: interfaces and docs are clear.
- Robust: works with assistive technologies where applicable.

(These are aligned with WCAG-style principles.)

---

## 3) Documentation accessibility

- Write in clear, plain language.
- Avoid unnecessary jargon.
- Use headings and lists for structure.
- Ensure links are descriptive (avoid “click here”).

Link to: `/Documentations/GLOSSARY_AND_DOMAIN_LANGUAGE.md`.

---

## 4) CLI / terminal UX (if applicable)

- Provide `--help` with clear descriptions.
- Use exit codes consistently.
- Avoid color-only distinctions; use text labels as well.
- Ensure output is readable in plain text (no heavy ASCII art).

---

## 5) Web/UI guidelines (if applicable)

- Color contrast meets accessibility standards.
- All interactive elements are keyboard-accessible.
- Form fields have labels.
- Images have alt text.
- Focus states are visible.

---

## 6) Inclusive language

- Avoid offensive or exclusionary terms.
- Prefer neutral, descriptive language.
- Be precise and respectful when referring to groups of people.

---

## 7) Testing and review

- Manual checks for keyboard navigation (UI).
- Automated accessibility checks (if applicable).
- Periodic review of documentation tone and clarity.
